# 密码生成引擎

English version: [Password Engine](../../en/features/password-engine.md).

## 概述

一个纯函数、不碰 DOM 的生成核心（`js/generator.js`）：把选项对象变成密码——Web Crypto 随机源、每类字符保底一个、以比特为单位评估强度。

## 背景

本项目 2026 年以单页静态站点起步，共三个提交。生成器从第一天起就与 UI 分离：同一份文件既要在浏览器运行（`window.PG.generator`），也要能在 Node 下被 `module.exports` 引入，从而脱离 DOM 穷尽测试逻辑。

## 问题

网页密码生成器有两种典型败法：使用 `Math.random()`（可预测、非密码学级）；用 `pool[Math.floor(random * pool.length)]` 抽字符——只要池大小不能整除随机源范围，输出就带偏。按类生成的实现还有第三种：以「检查后重试」实现「每类至少一个」，会让部分形态悄悄变稀有；或把各类代表字符**拼接在开头**，位置分布歪斜。

## 目标

- 每个字符都取自密码学安全随机源。
- 抽取均匀——UI 能产生的任何池大小都无取模偏差。
- 每个勾选类恰好保底一个字符，且位置分布不歪。
- 易输入、易朗读、易复述与黑名单是可组合的池过滤器，语义可预期。
- 全部逻辑可注入确定性 RNG 在 Node 中测试。
- 交付页面零依赖。

## 非目标（Non-Goals）

- **词表口令（passphrase）生成**——不做；本工具是字符生成器。
- **用户输入密码的强度检测**——强度条评估生成器设置，不评估任意输入。
- **可发音密码**——易朗读剔除同音字符，但不构造音节。
- **种子化 / 确定性生成**——重新生成的目的就是产出*不同*结果；主密钥 KDF 模式是另一种产品。
- **超过 64 的长度**——UI 决策；核心本身只要求 `length ≥ 勾选类数`。
- **自定义字符类**——四个固定类加黑名单已覆盖实际场景，不再引入类编辑器。

## 方案概览

一个 UMD 模块暴露 `buildClasses(opts)`、`generate(opts, rng?)`、`groupPassword(pw, size?, sep?)`、`entropyBits(length, poolSize)`、`strengthLevel(bits)`、`randomInt(rng, max)`。

- **随机源：** `defaultRng()` 每次从 `crypto.getRandomValues` 读一个 `Uint32Array(1)`（测试下回退 Node 的 `crypto.webcrypto`）。测试注入带种子的 LCG——结构测试要确定性，端到端用例走真加密源。
- **均匀性：** `randomInt` 用拒绝采样——先丢弃 ≥ `2³² − (2³² mod max)` 的值再取模，任何索引严格等概率。
- **类保底：** 每个存活类先取一个字符，其余位置从合并池填充，再做一次完整 Fisher–Yates 洗牌，使各位置可交换。
- **过滤：** `buildClasses` 依次应用易输入替换/剔除、易朗读替换/剔除、分隔符移除、黑名单移除；空类直接从数组剔除。`groupPassword` 是 `generate` 输出之上的纯排版。

## 详细行为

随版本交付的字符集：

| 类 | 集合 | 数量 |
| --- | --- | --- |
| 大写 | `A–Z` | 26 |
| 小写 | `a–z` | 26 |
| 数字 | `0–9` | 10 |
| 符号 | ``!@#$%^&*()-_=+[]{};:'",.<>?/~\`|`` | 32 |

全量池：**94** 个字符。

**易输入**（`TYPE_EXCLUDE = 0Oo1lIi2Zz5Ss8B6b9gq`）：

- 大写失去 `O I Z S B` → 剩 21。
- 小写失去 `o l i z s b g q` → 剩 18。
- 数字只剩 `347`。
- 符号整体替换为 ``!@#$%^&*-_=+?~``（13 个）。
- 易输入池：**55** 个字符。

**易朗读**（`SPEAK_EXCLUDE = BCDEGNPTVZbcdegnptvz17`）：

- 读音同源的字母大小写同剔：同发 /iː/ 音的 `B C D E G P T V Z`，加上 `N`（留下的 `M` 赢下 "em/en" 对）→ 大写、小写各剩 16。
- 数字失去 `1`/`7`（中文「一/七」）→ `02345689`。
- 符号整体替换为 `!@#$%*+=?`（9 个）——名字短、读音清晰。
- 易朗读池：**49** 个字符。

**两个高级过滤叠加：** 大写 13、小写 11（`l`/`q` 已被易输入剔除）、数字 `34`、可朗读符号 9 → **35** 个字符。16 位仍有约 82 比特。

**易复述分组**（`groupSep = '-' | '_'`）：选中的分隔符先从候选池剔除（符号 32 → 31，易输入符号 13 → 12；可朗读子集本就不含这两个），再由 `groupPassword` 以它按 4 位一组拼接。分隔符纯属排版——熵只计真实字符，复制得到分段字符串。

**黑名单**在以上所有过滤之后生效。任何过滤排空的类被跳过——既不贡献保底字符，也不进入合并池。生效顺序：易输入 → 易朗读 → 分隔符移除 → 黑名单 → 剔除空类。

**核心抛出的错误：**

| 条件 | 错误信息 |
| --- | --- |
| 没有任何类存活 | `no character class selected` |
| `length < 存活类数` | `length shorter than number of selected classes` |
| Web Crypto 不可用 | `Web Crypto API unavailable` |
| `randomInt` 收到非正 max | `max must be positive` |

**熵模型：** 显示比特 = `长度 × log2(合并池大小)`，四舍五入。有类保底时输出分布的真实最小熵略低于这个均匀上界（保底排除了「某类缺位」的字符串——在现实长度下那本就是天文数字级罕见）；刻意采用通用 log2 估计，使数值与任何密码强度参考一致。强度分级：<40 较弱 · 40–59 一般 · 60–79 强 · ≥80 极佳。

**UI 收敛：** 页面先把长度收敛到 4–64 再调核心，因此「长度小于类数」错误从 UI 不可达（最小 4 = 最多类数）；该错误存在的意义是保护程序化调用方。

## 用户体验

引擎本身无 UI；`js/app.js` 把它映射到页面：密码输出、熵读数、四段强度条与两个警告态（「请至少选择一种字符类型。」/「没有可用字符了——请调整黑名单。」）。基本控制（长度、四类字符、黑名单）在「02 — 设置」；三个高级模式（**易输入**、**易朗读**、**易复述** 及连字符/下划线分隔符切换）独占「03 — 高级选项」区块。任何选项变化即刻重新生成。见[使用 — 生成密码](../usage.md#生成密码)。

## 兼容性与历史影响

无历史行为受影响。核心公开接口（`buildClasses`、`generate`、`entropyBits`、`strengthLevel`、`randomInt` 及导出的字符集常量）自首个提交起保持稳定并有测试覆盖；未来任何对输出分布或错误契约的改动，必须先更新 CHANGELOG 并扩展测试。

## 数据与隐私影响

核心是纯计算：不触碰存储与网络。无新增 localStorage 键，无上传。（隐私声明见[隐私说明](../privacy.md)。）

## 性能影响

64 位密码至多约 130 次走 `getRandomValues` 的抽取；每次抽取以单字缓冲调用一次 `getRandomValues`，在任何能运行本页的设备上都远低于可感知阈值。除此之外不作任何量化声明。

## 当前局限

- 保底规则按**存活类**计数：高级过滤 + 黑名单叠加时，「保底」可能悄悄意味着比用户勾选数更少的类（UI 通过熵值如实反映池大小，但不会逐一标出被丢弃的类）。
- `entropyBits` 是均匀上界的估计，而非保底分布的精确最小熵（≥4 字符时差异可忽略）。
- 符号集刻意不含空格与所有非 ASCII 字符（Unicode 引号、中文标点……），以保证跨登录表单与编码安全。
